# 👁️ Система просмотров Stories и лайков (Activity Service)

## 🎯 Назначение

**Activity Service** автоматически просматривает Stories участников групп и ставит реакции (лайки) для повышения активности аккаунтов и имитации естественного поведения.

## 📋 Общая схема работы

```
Activity Service (каждые 6 часов)
    ↓
Для каждого активного аккаунта:
    ↓
Получить группы, закрепленные за аккаунтом
    ↓
Для каждой группы:
    ↓
Получить участников группы (до 30)
    ↓
Для каждого участника (до 20):
    ↓
Получить Stories пользователя
    ↓
Для каждой Story:
    ↓
Просмотреть Story (70% вероятность)
    ↓
Поставить реакцию (30% вероятность от просмотренных)
    ↓
Задержка между действиями
```

## 🔄 Цикл работы

### 1. Запуск цикла

- **Интервал**: Каждые **6 часов**
- **Длительность цикла**: Зависит от количества аккаунтов и групп (обычно 1-3 часа)

### 2. Обработка аккаунтов (`process_all_accounts`)

Для каждого активного аккаунта:
1. Проверяется лимит просмотров за сегодня
2. Если лимит не достигнут → обработка аккаунта
3. Задержка между аккаунтами: **120-300 секунд** (2-5 минут)

### 3. Обработка аккаунта (`process_account`)

Для каждого аккаунта:

1. **Проверка лимитов:**
   - Считаются просмотры за сегодня
   - Если `views_today >= 200` → пропускаем аккаунт

2. **Получение групп:**
   - Берутся группы, закрепленные за аккаунтом (`assigned_account_id`)
   - Только активные группы (`status = 'active'`, `can_post = True`)
   - Лимит: **10 групп** на аккаунт

3. **Для каждой группы:**
   - Получаются участники группы (до **30 участников**)
   - Фильтруются боты
   - Перемешиваются случайным образом
   - Обрабатываются до **20 участников**

4. **Задержка между группами**: **30-60 секунд**

### 4. Просмотр Stories пользователя (`view_user_stories`)

Для каждого участника группы:

1. **Проверка вероятности:**
   - 70% вероятность просмотра (`STORY_VIEW_PROBABILITY`)

2. **Получение Stories:**
   - Используется `GetPeerStoriesRequest` для получения Stories пользователя
   - Если Stories нет → пропуск

3. **Для каждой Story:**
   - Проверка: была ли просмотрена за последние 24 часа
   - Если была → пропуск (избежание дублей)
   - Еще раз проверка вероятности (70%)

4. **Просмотр Story:**
   - Просмотр происходит автоматически при `GetPeerStoriesRequest`
   - Сохраняется в БД: `StoryView` запись

5. **Реакция (лайк):**
   - **30% вероятность** поставить реакцию (`STORY_REACTION_PROBABILITY`)
   - Случайный выбор из: ❤️, 🔥, 👍, 😍, 💯
   - Используется `SendReactionRequest` с `ReactionEmoji`
   - Сохраняется в БД: `reacted = True`, `reaction_type = '❤️'` (например)
   - Задержка после реакции: **15-60 секунд**

6. **Задержка между просмотрами:** **10-45 секунд**

7. **Задержка между пользователями:** **5-15 секунд**

## 📊 Лимиты и ограничения

### Лимиты на аккаунт:
- **Максимум просмотров в день**: 200
- **Минимум просмотров в день**: 100 (планируется, сейчас не используется)
- **Максимум групп на аккаунт**: 10
- **Максимум участников на группу**: 20

### Проверки дублей:
- Story не просматривается повторно, если была просмотрена за последние **24 часа**

## 💾 Сохранение в БД

Все действия сохраняются в таблицу `story_views`:

```sql
CREATE TABLE story_views (
    id SERIAL PRIMARY KEY,
    account_id INTEGER REFERENCES accounts(id),
    user_id BIGINT,                    -- ID пользователя, чью Story просмотрели
    username VARCHAR(255),              -- Username пользователя
    story_id VARCHAR(255),              -- Формат: "{user_id}_{story_id}"
    reacted BOOLEAN DEFAULT FALSE,      -- Была ли поставлена реакция
    reaction_type VARCHAR(50),          -- Тип реакции (❤️, 🔥, и т.д.)
    viewed_at TIMESTAMP                 -- Время просмотра
);
```

## 🔧 Технические детали

### API методы Telegram:

1. **GetPeerStoriesRequest:**
   - Получение Stories пользователя
   - Автоматически регистрирует просмотр

2. **SendReactionRequest:**
   - Отправка реакции на Story
   - Использует `ReactionEmoji(emoticon='❤️')` для эмодзи-реакций

### Обработка ошибок:

- **FloodWaitError**: Ждем указанное время (максимум 300 секунд)
- **UserNotParticipantError**: Пользователь не в группе → пропуск
- **ChannelPrivateError**: Канал приватный → пропуск
- **ChatAdminRequiredError**: Нужны права админа → пропуск
- **RPCError**: Общие ошибки API → логируем и продолжаем

## ⚡ Производительность

### Временные характеристики:

- **Задержка между просмотрами**: 10-45 сек
- **Задержка после реакции**: 15-60 сек
- **Задержка между пользователями**: 5-15 сек
- **Задержка между группами**: 30-60 сек
- **Задержка между аккаунтами**: 120-300 сек (2-5 минут)

### Расчет времени цикла:

При 4 аккаунтах, 10 группах, 20 участниках:
- Просмотры: ~4 аккаунта × 10 групп × 20 участников × 0.7 (вероятность) × 25 сек (средняя задержка) ≈ **2-3 часа**

## 🎯 Цели системы

1. **Повышение активности аккаунтов** - просмотры и реакции делают аккаунты более "живыми"
2. **Имитация естественного поведения** - случайные задержки, вероятности
3. **Поддержание связей** - просмотры Stories участников групп укрепляют связи
4. **Избежание блокировок** - лимиты и задержки предотвращают FloodWait и баны
